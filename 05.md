# ORE-05

## The `/search/profiles` Endpoint

`draft` `optional`

This document defines the `/search/profiles` endpoint, which returns a ranked list of Nostr profiles matching a free-form query string.

---

## Endpoint

```
POST /search/profiles
```

Returns up to `limit` Profile objects matching the given query, sorted by rank in descending order.

## Request

| Field | Type | Required | Description |
|---|---|---|---|
| `query` | string | yes | A free-form search string. MUST NOT be empty. Clients SHOULD NOT send a `query` longer than 512 characters. |
| `algorithm` | string | no | The algorithm to use. If omitted, the provider MUST use the default algorithm for this endpoint as defined in [ORE-01](01.md). |
| `pov` | string | no | A point-of-view pubkey for personalised algorithms. MUST be provided if the requested algorithm requires it, as declared in the capability document. |
| `limit` | integer | no | The maximum number of Profiles to return. MUST be a positive integer. If omitted, the provider MUST use its own default. Clients SHOULD NOT request more than 1000. |

### Example Request

```json
{
  "query": "bitcoin developers",
  "algorithm": "semantic-v1",
  "limit": 20
}
```

## Response

The response is a JSON object with a `profiles` array and an optional `ttl`, identical in shape to the `/rank` response defined in [ORE-02](02.md).

| Field | Type | Required | Description |
|---|---|---|---|
| `profiles` | array | yes | An array of Profile objects matching the query, sorted by rank in descending order. Contains at most `limit` entries. |
| `ttl` | integer | no | A hint indicating how many seconds the returned results are expected to remain valid. Clients MAY cache the result for this duration. Clients MUST treat this value as a hint, not a guarantee. |

### Example Response

```json
{
  "profiles": [
    { "pubkey": "b7e2d...", "rank": 0.95 },
    { "pubkey": "cc481...", "rank": 0.88 },
    { "pubkey": "a3f9c...", "rank": 0.76 }
  ],
  "ttl": 300
}
```

## Errors

Algorithm selection, pov validation, and their associated error codes follow the rules defined in [ORE-01](01.md).

| Status | Reason |
|---|---|
| `400` | The request body is malformed or not valid JSON. |
| `422` | The `query` field is missing or empty. |
| `422` | The `query` value exceeds the maximum allowed length. |
| `422` | The `limit` value is not a positive integer. |
| `422` | The `limit` value exceeds the maximum supported by the provider. |
| `422` | The requested algorithm is not supported by this endpoint. |
| `422` | The requested algorithm requires a `pov` but none was provided. |
